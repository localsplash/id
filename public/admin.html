OAuth redirect URIs (postbacks)

Each provider's console must be told where to send the browser back after sign-in. Register these exact URLs — they follow APP_BASE_URL, so re-register after changing it.

oAuthConfig settings

Stored in NocoDB. A login method appears on the sign-in page only when all of its required keys are set. Values marked secret are write-only here. A key tagged env is pinned in this app's environment, which overrides the store — change it there and restart.

Application integrations

Apps register one endpoint and id pushes signed events to it — no polling, no cron. Sessions in each app are independent of the id session, so an app that is not listening will keep people signed in after you revoke them here.

On boot, each app calls:

POST /api/apps/register
{ "client_secret": "<ID_CLIENT_SECRET>",
  "name": "EchoWeb",
  "webhook_url": "https://app.<parent-domain>/id/events" }

→ { "secret": "…", "events": [ … ] }

id then POSTs each event to that URL:

X-Id-Event: session.revoked
X-Id-Event-Id: 1234
X-Id-Timestamp: 1774500000
X-Id-Signature: sha256=<hex>

{ "id": 1234, "type": "session.revoked",
  "occurredAt": "…", "data": { "iUserId": 7, "scope": "all" } }

The signature is HMAC-SHA256(secret, `${timestamp}.${rawBody}`). Receivers must verify against the raw body, reject a timestamp more than 300s off, compare in constant time, and answer 2xx only once the event is durably handled — retries mean handlers must be idempotent.

Missed events (app down past the retry schedule) are caught up once at boot via GET /api/events?since=<lastEventId>.
